Development Architecture & Structure

Technical blueprint: How the ecosystem is built, how data flows, and development milestones.

1. Core Tech Stack (The Engine Room)

App ko scalable aur smooth banane ke liye hum in 3 major technologies ka ecosystem banayenge:

Flutter (Frontend)

User App ka UI aur animations handle karega.

  • State Management: Provider ya Riverpod (Real-time changes handle karne ke liye).
  • UI/UX: Custom Paint aur BackdropFilter (Glassmorphism aur 3D ruby effects ke liye).
  • Local Cache: Hive ya SharedPreferences (Taaki offline ya slow internet me feed instantly load ho).

Django & Python (Backend)

App ka dimag (Brain). Saara logic aur master data yahan process hoga.

  • Database: PostgreSQL (Heavy relational data, Users, Posts, aur City/Mohalla tracking ke liye best).
  • API: Django REST Framework (DRF) JSON format me Flutter ko data dega.
  • Background Jobs: Celery + Redis (Election phases change karne aur bans lagane ke liye).

Firebase (Real-time Layer)

Instant actions bina delay ke dikhane ke liye.

  • Real-time DB: Sirf Like aur Support counters yahan rahenge taki click karte hi sabko update dikhe.
  • Authentication: Google Sign-In backend verification ke liye.
  • FCM: Push Notifications (Achaar Sanhita, Election Results, Warnings).

2. System Architecture Flow (Kaam Kaise Karega?)

A. Data Sync Flow (Hybrid Approach)

  • Jab user feed kholta he, Flutter pehle Django API se post ka text, images aur author fetch karega.
  • Uske turant baad, us post ki ID ke through Firebase se real-time "Likes" aur "Support" count fetch honge.
  • Fayda: Agar hazaar log ek sath kisi post par Like button daba rahe hen, to Django server crash nahi hoga. Saara load Firebase ka real-time engine sambhal lega, aur har raat Django Firebase se data sync karke apne paas permanent save kar lega.

B. Election Automated Engine (Celery)

  • Election dates manually handle karna impossible he. Iske liye hum Celery Beat (Task Scheduler) ka use karenge.
  • Agar chunav aayog ne date fix ki he, to Celery theek raat 12:00 AM par trigger hoga.
  • Example: Day 11 ki raat 12 baje, Celery automatically database me `is_code_of_conduct_active = True` kar dega. Agle hi second Flutter app post karne ka button disable kar degi.

3. Database Models (PostgreSQL Schema)

Django me jo tables banengi unka high-level structure:

  • User Table: Google_ID, Device_ID, Name, Image, Credibility_Score, Role (Citizen/Minister), Strike_Count, Ban_Until.
  • City Table: City_ID, Name, State, Samvidhan_HTML_Content.
  • Mohalla Table: Mohalla_ID, City_ID (Foreign Key), Name, Population_Count.
  • Cabinet Table: User_ID, Department_Name, Frame_Color, Appointed_By, Is_Active.
  • Post Table: Post_ID, User_ID, Mohalla_ID, Content, Type (Text/Poll/Ad/Announcement), Created_At.
  • Concern Table: Concern_ID, User_ID, Mohalla_ID, Image_URL, Description, Status (Open/Resolved/Priority).
  • Election Table: Election_ID, Type (City/Mohalla), Phase (Nomination/Prachar/Voting/Result), Start_Date.
  • Candidate Table: Candidate_ID, Election_ID, User_ID, Manifesto, Symbol, Vote_Count.

4. Security & Admin Workflow

Admin Hierarchy Logic

  • Superuser (You): Django admin me log in karke nai City aur unke City Admins (Election Commission) create karega.
  • City Admin (Election Comm.): Apne login se sirf apni City ka data dekh payega. Ye Django ke Row-Level Security / Multi-tenancy concept se hoga. Kandhla ka admin dusri city ka chunav nahi ched sakta.

Anti-Fraud / Abuse System

  • Profanity Filter: Flutter app me post submit hone se pehle local list se word check hoga. Fir Django API bhi regex se check karegi.
  • Vote Tampering: Voting table me `User_ID` + `Election_ID` ka ek 'Unique Constraint' laga hoga. Database level par ek user ka dusra vote fail ho jayega, chahe koi hacker app bypass kyu na kar le.

5. Development Roadmap (Kaam Kaise Shuru Hoga?)

Is project ko hum 6 phases me develop karenge taki testing proper ho sake.

Phase 1: Backend Foundation & DB Setup (Django)

Sabse pehle PostgreSQL set hoga. Users, City, Mohalla, aur Posts ke models banenge. Admin panel setup hoga aur CRUD operations ki APIs likhi jayengi.

Phase 2: Authentication & Mohalla Assignment (Flutter + Django)

Flutter me UI banana shuru hoga. Google Login integrate hoga, Device ID capture hogi. User profile banegi aur Mohalla selection dropdown live kiya jayega.

Phase 3: The Community Feed (Flutter + Firebase)

Text/Photo post karne ka system, Concerns raise karna. Firebase DB integrate karke real-time Likes aur Support system build karna. Cross-mohalla view logic implement karna.

Phase 4: The Election Engine (Celery + Django)

Sabse complex hissa. Election API endpoints, Parcha bharne ka form. Celery beat setup karna jo 15 din ki timeline (Nomination -> Prachar -> Achaar Sanhita -> Voting -> Results) ko automatically shift kare.

Phase 5: VIP Profiles, Frames & Samvidhan

App UI me 3D rubies, VIP borders, aur tags implement karna. Cabinet mantriyo ko adhikar (privileges) ki APIs authorize karna. Samvidhan (Constitution) ka premium page design karna.

Phase 6: Moderation, Ads & Load Testing

3-strike warning system live karna. Admin Ads pin karna. Voting day simulation karke jali traffic bhej kar load testing karna (Redis queue test). Play Store ki policies ke hisab se final review karna.
